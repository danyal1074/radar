# رادار خرید خودرو (Car Radar)

وب‌اپ فارسی/راست‌به‌چین برای نمایشگاه‌داران خودرو، به‌صورت **SaaS اشتراکی**: آگهی‌ها را ببینید، قیمت را با تخمین روز مقایسه کنید و برای فرصت‌های خرید هشدار بگیرید. بازار شروع: تربت‌حیدریه.

## وضعیت واقعی (صادقانه)

| بخش | وضعیت |
|---|---|
| ثبت‌نام/ورود، نشست امن، جداسازی داده‌ها | کامل (Supabase Auth + RLS در تولید؛ حالت توسعه با فایل محلی) |
| داشبورد، آگهی‌ها، فیلتر/مرتب‌سازی، جزئیات، ذخیره، پیگیری | کامل |
| قوانین هشدار + موتور هشدار + اعلان داخل سامانه (بدون تکرار) | کامل و تست‌شده |
| پلن‌ها، دورهٔ آزمایشی ۱۴ روزه، سقف قوانین/ذخیره‌ها | کامل |
| پرداخت | **کارت‌به‌کارت با تأیید دستی ادمین**. درگاه بانکی پیاده‌سازی **نشده** |
| پنل مدیریت (کاربران، پرداخت‌ها، پردازش‌ها، هزینهٔ API، ورود JSON) | کامل |
| **دیوار / شیپور** | **متصل نیست.** دسترسی مجاز (API رسمی/مجوز) لازم است. تا آن موقع: ورود دستی JSON در پنل مدیریت |
| **قیمت تخمینی Baravard** | **متصل نیست.** قرارداد API تأیید نشد و کلاینت عمداً بسته (fail-closed) است. بدون آن هشدار قیمتی تولید نمی‌شود |
| اتصال Supabase واقعی | کد و migration آماده است ولی **روی یک پروژهٔ Supabase واقعی آزموده نشده**؛ پیش از فروش، یک بار کامل روی پروژهٔ آزمایشی تست کنید |
| داده نمونه (برچسب «داده نمونه/قیمت نمونه») | فقط در حالت توسعه یا با `ALLOW_SAMPLE_DATA=true` |
| پیامک/پیام‌رسان/Push | پیاده‌سازی نشده (موتور هشدار مستقل از رابط است) |

## اجرای محلی (حالت توسعه)

```bash
npm install
npm run dev        # http://localhost:3000
```
بدون Supabase، داده‌ها در `.data/dev-store.json` ذخیره می‌شوند (فقط برای توسعه/دمو). برای ادمین‌شدن، ایمیل را در `ADMIN_EMAILS` بگذارید و با همان ایمیل ثبت‌نام کنید.

## راه‌اندازی تولید

1. در [supabase.com](https://supabase.com) پروژه بسازید.
2. محتوای `supabase/migrations/0001_init.sql` را در SQL Editor اجرا کنید (جدول‌ها، RLS، تریگر ساخت پروفایل و دورهٔ آزمایشی).
3. Authentication ← Providers: ایمیل/رمز. تأیید ایمیل را مطابق نیاز روشن/خاموش کنید و URL سایت را در URL Configuration بگذارید.
4. `.env.example` را به `.env.local` (یا متغیرهای محیطی میزبان) کپی و پر کنید: `NEXT_PUBLIC_SUPABASE_URL`، `NEXT_PUBLIC_SUPABASE_ANON_KEY`، `SUPABASE_SERVICE_ROLE_KEY` (فقط سمت سرور)، `ADMIN_EMAILS`، `CRON_SECRET`، `PAYMENT_CARD_NUMBER`، `PAYMENT_CARD_HOLDER`، `SUPPORT_CONTACT`.
5. `npm run build && npm start` (یا استقرار روی Vercel/سرور Node).
6. زمان‌بندی پردازش: هر N دقیقه `GET /api/cron/pipeline` با هدر `Authorization: Bearer $CRON_SECRET` (cron سیستم، Vercel Cron یا GitHub Actions). فاصله را بر اساس محدودیت منبع و هزینهٔ API تعیین کنید.

در تولید بدون Supabase برنامه عمداً اجرا نمی‌شود.

## مدل کسب‌وکار و تنظیم قیمت

قیمت و سقف پلن‌ها فقط در `lib/plans.ts` است (قیمت‌های فعلی **نمونه** هستند؛ پیش از فروش تنظیم کنید).

جریان فروش: ثبت‌نام ← ۱۴ روز آزمایشی ← انتخاب پلن در «اشتراک و پرداخت» ← واریز کارت‌به‌کارت و ثبت کد پیگیری ← تأیید ادمین ← فعال‌سازی/تمدید. مبلغ همیشه در سرور محاسبه می‌شود. پایان اشتراک یعنی قفل شدن پنل (فقط صفحهٔ پرداخت باز می‌ماند) و توقف هشدارها.

## فعال‌سازی Baravard

مستندات <https://baravard.com/api> را بخوانید (احراز هویت، endpoint، فیلدها، پاسخ، هزینه، نرخ، شرایط تجاری)، سپس `estimate()` در `lib/estimation/baravard.ts` را پیاده کنید و `BARAVARD_API_KEY` را بگذارید. کش، سقف روزانه/هر اجرا و ثبت هزینه از قبل در `lib/estimation/service.ts` آماده است.

## دیوار و شیپور

فقط با مجوز/API رسمی. یک `ListingSourceProvider` جدید بنویسید و در `lib/jobs/default.ts` ثبت کنید. تا آن زمان آگهی‌ها را در پنل مدیریت از JSON وارد کنید (فقط پیوند https این دو دامنه پذیرفته می‌شود).
